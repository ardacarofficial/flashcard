# 10 · v0.1 Sözleşmesi (paralel izler için)

v0.1 iskeleti ve sözleşmeleri `feat/v0.1-contract` dalında kuruldu. Bu doküman, paralel çalışan izlerin (L2–L5) **neye dokunabileceğini**, **neyi uygulayacağını** ve **hangi kararların sabit olduğunu** özetler. Ayrıntı için kodun kendisi (`///` belgeleri) esastır.

## 1. Crate'ler ve bağımlılık yönü

```
fc-core  ←  fc-api  ←──────────┐
   ↑  ↖                        │
   │   fc-storage ← fc-app ────┤  ← kabuklar: fc-cli, apps/desktop (Tauri), ileride fc-http / fc-mcp
   └── fc-providers ↗          │
```

| Crate | Ne içerir | Durum |
|---|---|---|
| `fc-core` | Saf alan: tipli UUIDv7 kimlikler (`IdGen`, `V7IdGen`), `Clock`/`Rng`, `Timestamp` (UTC ms), modeller (Deck, Preset, NoteType + yerleşik Classic, Note, Card, Tag, AttributeDef/Value), saf fonksiyonlar (deste yolu, etiket normalizasyonu, checksum/sort_field, sınıflandırma doğrulama + miras + hazır şablonlar, ayar şeması doğrulama) | **Tam**, testli |
| `fc-api` | v1 DTO'lar, metot kataloğu (`v1::catalog()`), hata modeli, zarflar, olaylar, TS üretimi (`gen-ts`) | **Tam** |
| `fc-providers` | AI/TTS/STT/çeviri/sözlük/lemmatizer + Scheduler/CardTypeEngine/AnswerChecker/HintStrategy/Importer/Exporter **imzaları** | İmza |
| `fc-storage` | `0001_init.sql` (03 §4'teki tüm tablolar + FTS5), migration çalıştırıcı, repo trait'leri, `Store`/`ReadTx`/`WriteTx`, `SqliteStore` iskeleti | Şema + arayüz; repo'lar **L2** |
| `fc-app` | Handler trait'leri, registry, dispatcher (`App::invoke`), oplog/undo sözleşmesi, olay yolu, iş kuyruğu arayüzü, modüller (dosya başına bir modül) | Altyapı çalışır; handler'lar `stub` → **L3** |
| `fc-cli` | `fc deck create/list`, `fc note add/list`, `fc undo/redo` (clap) | Düzen hazır, bağlantı **L3** |

> **Mimariden bilinçli sapma:** 03 §1'de "`api` → `app`" yazıyor. Burada `fc-api` sadece **sözleşme** (davranışsız tipler); `fc-app` ona bağlıdır, taşıma kabukları ikisine. Böylece handler'lar DTO'ları doğrudan kullanır, tip tekrarı olmaz.

## 2. Sabitlenen kararlar

| Konu | Karar |
|---|---|
| Metot adları | Çoğul alan + fiil: `decks.create`, `attributes.option.rename`, `oplog.undo`. Kablo adı sürümlü: `v1.decks.create`. Tek kaynak: `fc-api/src/v1/methods.rs` |
| Taşıma | Tek genel `invoke(method, params)` + olay akışı. JSON alanları `snake_case`. Yanıt: `InvokeResponse { status: ok/error }` |
| Hata | `ApiError { code, message_key, message, details, retryable }`. Kodlar `VALIDATION_*`, `NOT_FOUND_*`, `CONFLICT_*`, `PERMISSION_*`, `PROVIDER_*`, `IO_*`, `INTERNAL*`. Kod **asla** yeniden adlandırılmaz. Core/storage → API eşlemesi tek yerde: `fc-app/src/error.rs` |
| TS üretimi | `ts-rs` (07'deki specta yerine: kararlı, tek-invoke tasarımına yeter). Çıktı `apps/desktop/src/lib/api/generated/` + `methods.ts` (`Methods`, `RequestOf<M>`, `ResponseOf<M>`). `cargo test -p fc-api` güncelliği kontrol eder |
| Edition | 2021 (görev tanımı; 07'deki 2024'e geçiş ayrı karar) |
| Komut boru hattı | parse + `validate` → `BEGIN IMMEDIATE` → handler → oplog → commit → olaylar. Handler saat okumaz (`ctx.now`), kimliği `ctx.ids`'ten alır |
| Geri al | Her komut `CommandOutcome { response, inverse: Vec<InvokeRequest>, summary, events }` döner. Undo = son "do" batch'inin tersleri, ters sırayla, `ctx.call()` ile **yeni** bir batch'te (`kind = undo`, `reverts_batch_id`). Redo = undo batch'inin tersleri. `batch.execute`, `oplog.undo/redo` kendi alt çağrılarını kaydeder (`undo: false`) |
| Silme | Yumuşak (`deleted_at`). Create'in tersi `*.delete`, delete'in tersi `*.restore` |
| Etiketler | Kaynak `note_tags` (sıra `position`); `notes` tablosunda etiket sütunu yok |
| Sınıflandırma değerleri | `attribute_values` PK `(attr_id, entity_kind, entity_id, value)` (çoklu seçim = çok satır); satır biçimi `AttributeValue::to_stored()`; sayı/bool için `value_num` |
| Miras | Koleksiyon + atalar; aynı `key` birden çok seviyedeyse **en derin kazanır** (`effective_attribute_defs`) |
| Classic not türü | Sabit id `notetype::builtin::CLASSIC_ID`, alanlar `front`/`back`, şablon `forward`. Uygulama ilk açılışta tohumlar (`App::load_state`) |
| Checksum | FNV-1a 64 (16 hex), `unique` alanların HTML'siz + küçük harf metni |
| Modül anahtarları | `module_state` tablosu (ayarlardan ayrı) |
| Migration aralıkları | v0.1: 0001–0099, v0.2: 0100–0199, v0.3: 0200–0299, v0.4: 0300–0399, v0.5: 0400–0499 … |

## 4. Kurallar

1. `fc-core` ve `fc-api`'nin **public tiplerini** değiştiren iz, bunu raporunda açıkça yazar (ne, neden). Orkestratör birleştirmeyi buna göre sıralar.
2. Yeni metot = `methods.rs`'e bir satır + `gen-ts` + sahibi modülde handler. Registry testi (`registry_covers_the_catalog_exactly`) eksik/fazla metodu yakalar.
3. Elle DTO yok; TS dosyaları sadece `cargo run -p fc-api --bin gen-ts` ile değişir.
4. Kütüphane kodunda `unwrap`/`expect`/`panic`/`todo!`/`unimplemented!` yok (clippy uyarı → CI hata). Herkese açık her öğe belgelenir (`missing_docs`).
5. İz kendi sahibi olmadığı crate'te değişiklik gerekiyorsa küçük tutar ve raporlar.

## 5. Komutlar

```bash
export CARGO_BUILD_JOBS=4
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p fc-api --bin gen-ts            # TS tiplerini üret
cargo run -p fc-api --bin gen-ts -- --check # CI kontrolü
```
