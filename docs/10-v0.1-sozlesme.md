# 10 · v0.1 Sözleşmesi (paralel izler için)

v0.1 iskeleti ve sözleşmeleri `feat/v0.1-contract` dalında kuruldu. Bu doküman, paralel çalışan izlerin (L2–L5) **neye dokunabileceğini**, **neyi uygulayacağını** ve **hangi kararların sabit olduğunu** özetler. Ayrıntı için kodun kendisi (`///` belgeleri) esastır.

## 1. Crate'ler ve bağımlılık yönü

```
fc-core  ←  fc-api  ←──────────┐
   ↑  ↖                        │
   │   fc-storage ← fc-app ────┤  ← kabuklar: fc-cli, apps/desktop (Tauri), ileride fc-http / fc-mcp
   └── fc-providers ↗          │
```

| Crate | Ne içerir | Durum |
|---|---|---|
| `fc-core` | Saf alan: tipli UUIDv7 kimlikler (`IdGen`, `V7IdGen`), `Clock`/`Rng`, `Timestamp` (UTC ms), modeller (Deck, Preset, NoteType + yerleşik Classic, Note, Card, Tag, AttributeDef/Value), saf fonksiyonlar (deste yolu, etiket normalizasyonu, checksum/sort_field, sınıflandırma doğrulama + miras + hazır şablonlar, ayar şeması doğrulama) | **Tam**, testli |
| `fc-api` | v1 DTO'lar, metot kataloğu (`v1::catalog()`, alan başına `v1/methods/<alan>.rs`), hata modeli (kodlar `src/error_codes/<alan>.in`), zarflar, olaylar, TS üretimi (`gen-ts`) | **Tam** |
| `fc-providers` | AI/TTS/STT/çeviri/sözlük/lemmatizer + Scheduler/CardTypeEngine/AnswerChecker/HintStrategy/Importer/Exporter **imzaları** | İmza (bilinçli; ilk gerçek uygulama v0.2+) |
| `fc-storage` | `0001_init.sql` (03 §4'teki tüm tablolar + FTS5), klasörden otomatik toplanan checksum'lı migration'lar, alan başına repo trait'leri (`repo/<alan>.rs`), `Store`/`ReadTx`/`WriteTx`, `SqliteStore` (tek yazıcı + okuma havuzu) ve tüm repo'ların SQLite uygulaması | **Tam**, testli |
| `fc-app` | Registry, dispatcher (`App::invoke`), oplog + birebir geri al/yinele, olay yolu, iş kuyruğu arayüzü, şemalı ayarlar; katalogdaki **her** metodun gerçek handler'ı (modül başına bir dosya); `testing` özelliği: `MemStore` + `store_suite!` | **Tam**; kabul testi `acceptance.rs`, servis testleri 3 depoda |
| `fc-cli` | `fc deck create/list/rename/move/delete/restore`, `fc note add/list/edit/delete/restore`, `fc attribute define/apply-template/set/list/option {add,rename,reorder,delete}`, `fc undo/redo` + genel `fc call <metot> [<json>\|-]` (yalnız public metotlar); `--attr` anahtar **veya** ad; TR/EN çıktı (`--lang` / `app.locale`) | **Tam**; gerçek ikiliyle e2e testi |
| `fc-desktop` | Tauri 2 kabuğu (tek `invoke` + `fc://event`, başlangıç hatasında yerel hata penceresi) + Svelte 5 arayüz, TR/EN i18n (`locales/<dil>/<özellik>.json`) | **Tam** (Windows CI henüz koşmadı) |

> **Mimariden bilinçli sapma:** 03 §1'de "`api` → `app`" yazıyor. Burada `fc-api` sadece **sözleşme** (davranışsız tipler); `fc-app` ona bağlıdır, taşıma kabukları ikisine. Böylece handler'lar DTO'ları doğrudan kullanır, tip tekrarı olmaz.

## 4. Kurallar

1. `fc-core` ve `fc-api`'nin **public tiplerini** değiştiren iz, bunu raporunda açıkça yazar (ne, neden). Orkestratör birleştirmeyi buna göre sıralar.
2. Yeni metot = alanın `methods/<alan>.rs` dosyasına bir satır (yeni alan: yeni dosya + `domains!`'e bir ad) + `gen-ts` + sahibi modülde handler. Registry testi (`registry_covers_the_catalog_exactly`) eksik/fazla metodu yakalar. Ayrıntılı tarif: §10.
3. Elle DTO yok; TS dosyaları sadece `cargo run -p fc-api --bin gen-ts` ile değişir.
4. Kütüphane kodunda `unwrap`/`expect`/`panic`/`todo!`/`unimplemented!` yok (clippy uyarı → CI hata). Herkese açık her öğe belgelenir (`missing_docs`).
5. İz kendi sahibi olmadığı crate'te değişiklik gerekiyorsa küçük tutar ve raporlar.

### 6.1 Storage API changes for L3

Sözleşme incelemesinden sonra gelen değişiklikler (`crates/fc-storage/src/repo.rs`). **Kırıcı** olanlar ⚠ ile işaretli.

| Trait | Değişiklik | İmza |
|---|---|---|
| `NoteWrite` ⚠ | Ana deste parametresi; etiketler artık var olmalı | `insert_note(&mut self, note: &Note, home_deck: DeckId, search_text: &str)` |
| `NoteWrite` ⚠ | Etiket yaratmaz (eksik → `NotFound{tag}`); ana desteyi korur | `update_note(&mut self, note: &Note, search_text: &str)` (imza aynı) |
| `NoteWrite` | Yeni | `set_note_home_deck(&mut self, id: NoteId, home_deck: DeckId) -> StorageResult<()>` |
| `NoteRead` | Yeni | `note_home_deck(&self, id: NoteId) -> StorageResult<Option<DeckId>>` |
| `NoteListRow` ⚠ | Yeni alan | `home_deck_id: DeckId` |
| `TagWrite` | Yeni (kimlik çağırandan) | `ensure_tags(&mut self, tags: &[(TagName, TagId)], now: Timestamp) -> StorageResult<Vec<EnsuredTag>>`; `EnsuredTag { id, created }`, giriş sırasında |
| `TagWrite` ⚠ | `now` alır, etkilenen notların `updated_at`'ini günceller, sayı yerine id listesi döner | `merge_tag(&mut self, from: TagId, into: TagId, now: Timestamp) -> StorageResult<Vec<NoteId>>` |
| `DeckWrite` | Yeni: silme kuralı | `trash_deck_subtree(&mut self, deck: DeckId, at: Timestamp) -> StorageResult<DeckTrashSet>` |
| `DeckWrite` | Yeni: çöpten geri yükleme | `restore_deck_subtree(&mut self, deck: DeckId) -> StorageResult<DeckTrashSet>` |
| `DeckWrite` | Yeni: undo/redo için kimlik listeleriyle | `set_trash_set_deleted(&mut self, set: &DeckTrashSet, deleted_at: Option<Timestamp>) -> StorageResult<u32>` |
| `DeckTrashSet` | Yeni kayıt | `{ decks: Vec<DeckId>, cards: Vec<CardId>, notes: Vec<NoteId> }` (id'ye göre sıralı, yalnız gerçekten değişenler) |
| `AttributeRead` | Yeni | `effective_attribute_defs_for_note(&self, note: NoteId) -> StorageResult<Vec<(AttributeDef, usize)>>` (ana deste, `target = note`) |
| `AttributeRead` | Yeni | `effective_attribute_defs_for_card(&self, card: CardId) -> StorageResult<Vec<(AttributeDef, usize)>>` (kartın destesi, `target = card`) |
| `AttributeWrite` | Yeni: çağıranın id'si + sıra indeksi | `insert_attribute_option(&mut self, attr: AttributeDefId, option: &AttributeOption, index: usize, now: Timestamp)`; id çakışması → `Constraint{"attribute_option_id"}` |
| `AttributeWrite` | Yeni: merge (`Some(into)`) / delete (`replace_with`) | `remove_attribute_option(&mut self, attr, option: AttributeOptionId, replace_with: Option<AttributeOptionId>, now) -> StorageResult<OptionRemoval>` |
| `AttributeWrite` | Yeni: tam ters | `restore_attribute_option(&mut self, attr, removal: &OptionRemoval, now)` |
| `OptionRemoval` | Yeni kayıt | `{ option: AttributeOption, index: usize, replaced_with: Option<AttributeOptionId>, moved: Vec<EntityRef>, dropped: Vec<EntityRef> }` |
| `StorageError::InvalidCursor` | Belge | L3 → `VALIDATION_INVALID_PARAMS` |

Notlar:
- Seçenek işlemleri sıralı listede çalışır ve `order`'ı `0..n` yeniden numaralar (`AttributeDef::add_option/remove_option` ile aynı), tanımın `updated_at = now`. Çoklu seçim değerleri seçenek sırasıyla döner (yeniden sıralamadan sonra da).
- Merge'de varlık zaten `into`'ya sahipse `from` satırı silinir (`dropped`), değilse `into`'ya taşınır (`moved`). `restore` tam tersini tek işlemde yapar.
- `set_decks_deleted` artık açıkça "basamaksız"; deste silme komutu `trash_deck_subtree` kullanmalı, tersi `set_trash_set_deleted(&set, None)`.
- Etkin tanımlarda gölgeleme `key` ile hedef süzmesinden **önce** yapılır (sorgu dilinde `key` tek ad alanı).

## 7. L3 notları (uygulama + CLI)

- **Sözleşme değişiklikleri:**
  - `AddAttributeOption.id` (isteğe bağlı; redo için kalır).
  - Katalog makrosu metot başına `Public | Internal` görünürlüğü alır. **Internal** metotlar yalnızca uygulama içinden (ters çağrılar, undo/redo) çağrılır; IPC/CLI/`batch.execute` `PERMISSION_DENIED` döner, `modules.list` ve üretilen TS `Methods` haritası bunları içermez. İlk ikisi:
    - `attributes.option.restore` — `option.delete/merge`'ün tersi: seçeneği eski kimliği ve **sıra indeksiyle** geri ekler, her varlığın değerini aynen yazar; kendi tersi `option.delete{replace_with: replaced_by}`. Varsayılan değişmişse ayrıca `attributes.update` gelir.
    - `decks.restore_affected` — `decks.delete`'in tersi: silinen deste/not/kart **kimlik listelerini** taşır ve tam olarak onları geri getirir. Çöp kutusundaki `decks.restore` ise `deleted_at == deste.deleted_at` eşleşmesiyle çalışır.
  - `notes.home_deck_id`: `NoteDto.home_deck_id`; `notes.create.deck_id` = ev destesi (+ kartların destesi); `notes.update.deck_id` (isteğe bağlı) ev destesini değiştirir, kartlar yerinde kalır. Not düzeyi sınıflandırmalar ev destesinden, kart düzeyi olanlar kartın destesinden çözülür.
- **Oplog sırası:** her komut kendi `seq`'ini iç çağrılarından **önce** ayırır (her derinlikte), sonra doldurur; geri al girişleri ters `seq` sırasıyla çalıştırır.
- **Erişim denetimi tek yerde:** `registry::ensure_invocable` (görünürlük → yetki → modül açık mı) hem üst düzey `invoke` hem `batch.execute`'un her iç çağrısı için çalışır; batch içinde modül durumu o anki işlemden okunur.
- **Kimlikler yalnızca uygulamanın `IdGen`'inden:** eksik etiket satırlarını uygulama oluşturur (`TagId` üretip `upsert_tag`), depolama hiçbir kimlik üretmez; `MemStore` olmayan etikete başvuran notu reddeder.
- **`AttributeValue::from_stored(def, rows)`:** imza `kind` yerine `&AttributeDef` alır; `multi_enum` seçenek sırasına göre döner. Depolamadaki tek çağrı yeri buna göre güncellenmeli.
- **Depolama ekleri (`support/store_ops.rs`):** deste alt ağacını çöpe atma/geri getirme (kimlik listeleriyle), indeksle seçenek ekleme, değişeni döndüren seçenek silme/birleştirme şimdilik bugünkü repo ilkelleriyle burada; entegrasyonda her fonksiyonun gövdesi tek bir depolama çağrısına bağlanır, imzalar değişmez.
- **Geçersiz imleç:** `VALIDATION_INVALID_PARAMS` (`details.field = "cursor"`). Birleştirmeden sonra `error.rs`'e `StorageError::InvalidCursor(_) => invalid_cursor(msg)` kolu eklenmeli (bu dalda varyant henüz yok; `MemStore` `Corrupt{table:"cursor"}` kullanır).
- **Geri al:** Tersi boş komutlar (no-op) oplog'a yazılmaz, geri al adımı olmaz. Geri al/yinele batch'leri "katı" kuralları (uygulanabilirlik, zorunlu değer) atlar, değerleri yine doğrular.
- **`notes.update` sınıflandırmaları:** listelenenler ayarlanır/temizlenir, listelenmeyenlere dokunulmaz.
- **Deste konumu** kardeşler arası sıralama anahtarıdır (eşitlikte ada göre); taşıma kardeşleri yeniden numaralamaz.
- **Test paketi:** `fc_app::testing` (`testing` özelliği): `MemStore` + depolamadan bağımsız `store_suite!`. L2 aynı paketi `SqliteStore` ile çalıştırmalı:
  `mod sqlite_suite { fc_app::store_suite!(|| -> Arc<dyn Store> { Arc::new(SqliteStore::open_in_memory().unwrap()) }); }`
- **L2'ye beklenti:** `list_oplog_batches` en yeniden eskiye, `before` hariç; `entities_with_option` çöp kutusundaki notları da döndürür; `insert_note`/`update_note` etiket satırlarının **var olduğunu varsayar** (uygulama önceden oluşturur; depolama `TagId` üretmez); `Note.home_deck_id` sütunu kalıcı tutulur.

## 8. Entegrasyon notları (`feat/v0.1-integration`)

- **Ana deste tek kaynak:** `fc_core::note::Note.home_deck_id`. `NoteWrite::insert_note(note, search_text)` (ayrı `home_deck` parametresi kalktı), `update_note` sütunu da yazar, `NoteListRow.home_deck_id` kalktı (`row.note.home_deck_id`). `note_home_deck`/`set_note_home_deck` kolaylık olarak duruyor.
- **`store_ops` bağlandı:** `trash_deck_subtree` → `DeckWrite::trash_deck_subtree`, `restore_trashed` → `set_trash_set_deleted(.., None)`, çöpten geri yükleme → `restore_deck_subtree` (kartsız ana-deste notları da döner), `insert_option` → `insert_attribute_option`, `remove_option` → önceki değerleri okuyup `remove_attribute_option`. Eksik etiketler `ensure_tags` ile (kimlik `IdGen`'den).
- **Hata eşleme:** `StorageError::InvalidCursor` → `VALIDATION_INVALID_PARAMS` (`field: cursor`); `NotFound{attribute_option}` → `NOT_FOUND_ATTRIBUTE_OPTION`. `MemStore` artık gerçek varyantı döndürür ve depolamanın tüm yeni trait metotlarını uygular.
- **Test paketi:** `store_suite!` üç depoda koşar: `MemStore`, `SqliteStore::open_in_memory`, geçici dosyada `SqliteStore` (`fc_app::testing::TempSqlite`).
- **Masaüstü:** `fc-desktop` kök workspace üyesi. `invoke(command, payload)` → `App::invoke(.., Actor::User)` (iç metotlar `PERMISSION_DENIED`), veritabanı uygulama veri klasöründe `collection.db`, olaylar `EventEnvelope` olarak `fc://event`'e. Frontend tipleri `src/lib/api/generated`'den; mock taşıma yalnız geliştirmede.
